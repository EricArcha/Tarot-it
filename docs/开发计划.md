# Tarot-it 开发计划

2026-11-25 · v1

## 产品范围

Tarot-it 是一个可公开分发的塔罗 Skill。用户可以在 OpenClaw、Hermes Agent、Codex 和 Claude Code 对话中选牌阵和牌组、抽牌、看真实牌面，再决定是否解读。首版用简体中文交互和解读，牌名附英文，方便查对原典。四个 Agent 共用同一套牌库、规则和抽牌程序，各自用宿主支持的方式显示图片。

安装包包含 78 张高清 Rider–Waite–Smith（韦特）牌面、78 张牌的中文正逆位资料和 8 套牌阵。安装完成后，抽牌、查牌义和生成牌桌均由本地程序完成，Skill 本身无需网络、账号或 API Key。宿主 Agent 的模型调用沿用其自身配置。按公开包标准验收，实际公开时间由 Eric 决定。

| 牌义底本 | 以 Arthur Edward Waite 的《The Pictorial Key to the Tarot》为准，Part II 核图片与象征，Part III 核占卜牌义，按牌名和章节记录出处。明确区分韦特原典里的解释和适用于现代对话的原创中文转述。 [原典目录](https://en.wikisource.org/wiki/The_Pictorial_Key_to_the_Tarot) · [原典扫描](https://en.wikisource.org/wiki/File:The_Pictorial_Key_to_the_Tarot.pdf) |
| 现代校读 | 2026-11-26 经 Eric 确认，用 Biddy Tarot 官网覆盖全套的正逆位索引逐牌对照，用 Joan Bunning 的作者课程第 17 课校准逆位用法。原先拟选的 Pollack 与 Greer 著作保留为可补充的书目。遇到分歧保留韦特原典依据，在逐牌记录里说明采用的角度。公开库收录原创中文、可核查的出处和编辑结论。 [Biddy Tarot 全套索引](https://biddytarot.com/tarot-card-meanings/) · [Bunning 逆位课](https://www.learntarot.com/less17.htm) |

牌库以逐牌 JSON 为源文件，可用普通文本审阅和维护。每张牌记录 ID、双语牌名、牌类、花色或编号、两至四个可在图中核对的细节、正逆位分别适用的主题和中文说明、原典定位、现代校读定位及牌图清单 ID。每个方向是一条独立释义。逆位可能表现为受阻、过度、内收或转向，逐牌决定，不能用正位词语机械取反。资料编辑逐条核对 78 张牌、156 条释义与插图，重点复核力量 VIII、正义 XI、愚者编号、宫廷牌和容易混淆的中文牌名。牌义审核应能从任一条释义回查到对应出处和校读记录。

## 一次占卜怎么走

1. **进入。** 用户明确说要抽牌、占卜或调用 `tarot-it` 时进入。单纯谈塔罗历史、牌图或牌义时按对应问题回答。系统先判断是否适合占卜。允许用户心里默想，也允许他自愿给一句背景。新一轮先问还未确定的牌阵和牌组，等用户回答后洗牌。牌组可选大阿尔卡纳 22 张、小阿尔卡纳 56 张或全套韦特 78 张。已指定的选项直接沿用。明确授权代选时用三张当下和全套韦特。快速抽牌只跳过切牌、选号和翻牌确认。
2. **摆牌。** 默认启用正逆位，开抽前可切换成只看正位。仪式模式每轮只问当前需要的选择，给「切牌」「自己选牌」「替我抽」三个入口。切点为 1 至所选牌组张数减 1，切过后还可选号或顺抽。自行选牌从 1 至所选牌组张数中选足牌阵需要的不同位置，按输入顺序填进牌位，12 张允许一次输完。该数字指向已经洗好的牌堆位置。确认前只展示牌背、位置和常用操作，不泄露牌名和方向。
3. **揭牌。** 仪式流程等用户明确确认。「直接抽」等明确快速指令可直接走到揭牌。先提交并锁定牌阵快照，再按牌位显示真实牌图、牌名和正逆位。输入重复、越界或数量不对时让用户改输入，保留原来的牌堆。重新显示、补传、补做全景和请求解读均使用同一结果。用户明确发起另一轮才创建新牌堆。
4. **按请求解读。** 默认亮牌后停住，最多提示「想听解读的话，说一声就行」。用户事先说「抽完帮我解读」也算授权。先完整交付牌面，再解释。宿主能分段提交时用两段，同一消息交付时把牌图与牌位放在解读之前。需要补传才能看到图时先完成补传。
5. **结束或恢复。** 用户可取消未揭牌的占卜，也可要「再看一次上一轮」。上下文或状态不足以确定用户指的是哪一轮时，只澄清轮次。运行目录过期或已清理时，允许用户提供上次牌名和方向做解读。

解读从牌位和画面中选一条能解释的线索，再联系用户的问题，最后给一个可自行判断的观察点。逆位按每张牌的具体情境解释。单张用一小段，三张先逐位再给整体理解，复杂牌阵可分组，但每个牌位都能找到对应解释。用户想查时再给牌义出处。比如宝剑二出现在「盲点」位，可以说「牌里的人蒙着眼，手上两把剑都还端着。放到这件事上，你可能还缺一个能帮你判断的信息。你最想先弄清楚什么？」

## 四个平台如何发图

已核对下列官方文档。安装路径决定 Skill 能否加载，发图方式取决于实际对话端、权限和运行位置。下表记录首版的交付方式和各端的验收口径。

| Agent 与首发验收端 | 安装与图片交付接口 | 验收要点 |
| --- | --- | --- |
| **OpenClaw · Control UI / WebChat** | 把完整目录放到活动 workspace 的 `skills/tarot-it/`。自动可见回复模式用最终消息中的独立 `MEDIA:` 行引用本地 PNG/JPEG。宿主提供结构化回复时用 `mediaUrl` / `mediaUrls`。若部署设置为 `message_tool_only`，改用当前对话的 `message(action=send)`，按官方字段传 `media` 或 `attachments`。 [Skill 安装](https://docs.openclaw.ai/tools/skills) · [富输出协议](https://docs.openclaw.ai/reference/rich-output-protocol) | 核对官方附件字段、Gateway 读取权限及同一结果的补传方式。保留临时环境的 Control UI 记录。 |

公共输出为牌位清单和自包含 `spread.html`。HTML 用内置牌图生成，无外部字体、脚本或网络请求，包含逆位方向、用于手机阅读的单列布局，以及可查看的高清单牌。复杂牌阵优先给一张 PNG 全景加详细牌桌，避免十几张附件把对话冲散。安装有 Pillow 的环境可选本地合成全景，基本运行使用 Python 标准库。能显示图片而无法生成全景的宿主，交付按牌位排序的图片和对应布局的 HTML。大图超过宿主限制时，用较小预览或分批发送，高清仍可在离线牌桌查看。生成的文件应在当前用户可打开或可下载的位置。异机执行时，服务端文件路径只有在宿主已把文件交付给用户后才算成功。

## 实现结构和状态

遵循 Agent Skills 格式，目录名和 `SKILL.md` 的 `name` 都用 `tarot-it`。`SKILL.md` 只保留触发条件、状态流程、闸口和怎样调用工具。牌义按抽中牌和方向读取。宿主差异写入一份交付说明，保留一个抽牌实现。 [Agent Skills 规范](https://agentskills.io/specification)

```text
tarot-it/
  SKILL.md
  assets/deck/        高清牌面、预览和来源清单
  references/         逐牌牌义、牌阵、交付说明和署名
  scripts/tarot.py    本地运行器
```

- **调用。** Python 3.10+。计划提供 `check`（素材、目录和环境预检）、`start`（准备牌堆）、`select`（切牌或选号）、`reveal`（提交快照）、`show`（从快照生成文件）、`meaning`（查牌库）、`clear`（清除本次状态）。JSON 返回运行 ID、生命周期状态、素材版本和错误代码，揭牌之后才返回卡牌 ID 与方向。口语问题由 Agent 在对话里处理，脚本不接收问题原文。
- **随机。** 每轮用操作系统随机源洗入所选牌组的全部牌，选牌不放回。开启逆位时，每张方向独立等概率，结果与牌堆一起固定。方向与问题、选数和模型输出无关。开发测试可注入确定的随机源，发布入口使用系统随机。揭牌后图片和牌义都靠卡 ID 与方向定位，模型不能选牌或填补一个失败的抽牌结果。
- **状态。** 在宿主许可的私有本地目录使用 `sqlite3` 保存短期状态，记录轮次、宿主隔离标识、牌阵参数、固定的牌堆及结果、素材版本、时间。同一次开局重试沿用原请求标识，回到同一个轮次。重复提交在事务里返回已有快照。交付失败单独重跑 `show`，文件写完后再发布路径。默认结果保留 24 小时，清理后只留随机请求标识的摘要和关闭原因，防止旧请求重新洗牌。问句、解读、联系人和身份资料不写入 Skill 状态。宿主聊天记录遵循宿主设置。共享部署要验证记录和附件按会话隔离，再开放该部署场景。

## 边界和闸口

| 时点 | 处理规则 |
| --- | --- |
| 抽牌前判断 | 日常感情、工作、人际和自我反思可继续。涉及揣测第三方内心、求一个必然结局或精确日期时，先给一个以可观察事实或自身选择为中心的改写，由用户决定是否用它抽。 |
| 高风险问题 | 涉及诊断、治疗/停药、法律结论、投资买卖等重大决定时，停在抽牌前，把回应限于所需的现实信息、专业渠道与眼前安全。是否停药、继续用药或调整剂量，由了解具体情况的医生或药师判断。用户明确改成低风险反思后方可继续。遇到自伤、伤人、现实危险或因被害信念陷入恐惧时，中止仪式，优先处理眼前安全与现实求助，避免用牌确认恐惧或解释危机。 |
| 翻牌前检查 | 检查真实素材、执行和展示路径。仪式模式需要明确同意揭牌。无法执行本地随机程序或缺失对应素材时，告诉用户具体缺项。不得用编出的随机结果、远端替代图或模型生成图交差。 |
| 解读前检查 | 牌面已经交付且用户明确要求解读。若用户在亮牌后转向高风险问题，应用同一边界。像死神、高塔这类牌用象征解释，禁作死亡、疾病、灾祸的断言。 |
| 重抽与停止 | 不满意要求重抽时先提供查看原结果的选择，明确另开一轮后再抽。用户说停就停。对「抽到对方会回来为止」这类反复求确定答案的指令，停下并把话题拉回他能判断或处理的事情。 |
| 文件与交付 | 只从固定的牌图清单读取输入，只在宿主许可目录生成文件。用户自由文本不拼进 shell 命令、路径、HTML 或附件指令。附件只交付本次牌面到当前对话。共享入口无法验证隔离时，不启用共享部署。 |
