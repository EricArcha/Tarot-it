# Tarot-it v1 实施规格

[已确认的开发计划](开发计划.md) 定义产品范围。本规格定义安装、运行和验收合同。

## 产品验收

| 项目 | 可观察结果 |
| --- | --- |
| P1 牌库 | 离线提供同版 Rider–Waite–Smith 牌组的 22 张大牌及四花色各 14 张，原文件短边 ≥1000、长边 ≥1800。每张有实际像素、固定源版本、权利依据、SHA-256 和双语名字。 |
| P2 牌义 | 78 份逐牌资料，正逆位各有独立中文释义和主题，附画面细节、韦特原典定位及经确认的现代校读。`sources.modern_review` 记载已核对状态、Biddy Tarot 逐牌链接、Bunning 第 17 课方法链接和原创编辑结论。 |
| P3 牌阵 | `single` 1 张、`present` 3 张、`timeline` 3 张、`relationship` 5 张、`dilemma` 5 张、`horseshoe` 7 张、`celtic-cross` 10 张与 `annual` 12 张。牌位顺序由配置固定。默认 `present`。年度缺省从本机下一个自然月起，已显式指定年时从 1 月起。 |
| P4 抽牌 | 用户可心中默想、切牌、选 1–78 的数字、交给 Agent 抽或直接快速抽。正式洗牌来自操作系统随机源，整轮不放回。正逆位模式每张方向独立等概率。只看正位仍洗整副牌。错号、刷新、进程重试和重复确认均保留原轮次。 |
| P5 亮牌 | 先提交结果，再交付牌位、名字、方向、图片和离线路径。带原装高清图的自包含 HTML 可断网、移动后打开。窄屏按牌位顺序阅读。凯尔特十字桌面图有交叉位，年度有年月。 |
| P6 解读 | 只有明确同意且牌面交付后才解读。提前同意可沿用；用户撤回即停止。读对应方向、逐位给生活化解释，复杂牌阵也须覆盖全部牌位。理解与建议建立在可观察的现实信息及用户可控的选择上。 |
| P7 闸口 | 普通问题通过。第三方读心、必然结果或具体日期先请用户确认问题改写。医疗、法律、投资重大决策先停抽，将回应限于现实信息、专业渠道和眼前安全。危机中断全流程，优先回应现实安全。牌义查询与占卜揭牌走各自的流程。 |
| P8 平台 | 同一个 Skill ZIP 可分别安装到 OpenClaw、Hermes、Codex 和 Claude Code。OpenClaw、Hermes 的交付按官方接口适配并提供离线回退。Codex Desktop 记录聊天内显示效果，Codex CLI 与 Claude Code 从实际占卜打开同一份离线牌桌。 |

## 本地接口

`python3 scripts/tarot.py [--state-dir PATH] <command>`。相对于 Skill 路径加载内置文件。只接受参数表中的数据，问题和解读留在当前对话。所有命令用 JSON 返回。成功退出 0，输入或状态问题退出非零并给 `error.code` 与可读消息。默认使用当前工作目录 `.tarot-it`，宿主可指定获准的私有状态目录。正向命令中 `scope` 与 `request` 是 Agent 生成并绑定当前聊天的独立随机 UUID，`run_id` 由程序生成。共享部署必须由宿主提供真正的会话隔离。

| 命令 | 参数与语义 |
| --- | --- |
| `check` | 加载数据、核验文件、测试状态目录可写，可用 `--output-root` 验证交付目录。`--full` 校验全部图像清单哈希。 |
| `spreads` | 返回所有牌阵及牌位。 |
| `start` | `--scope --request [--spread] [--upright-only] [--year]`。同一 `scope + request` 和参数回同一轮，参数不同则报冲突。过期或取消的请求返回明确错误，另开一轮用新请求。返回 `prepared` 与牌数，无牌名、ID、翻转方向和牌堆种子。年参数只用于年度。 |
| `select` | `--scope --run [--cut n] [--positions n …]`，至少提供一项。未翻牌前可更新，切点基于原洗好的牌堆，可在同一次调用中设置切点和选位。选位按输入顺序对应牌位。相同切点重试结果不叠加。 |
| `reveal` | `--scope --run`。Agent 只有取得揭牌授权才调用。单事务固定结果，重复调用返回同一张序和方向，省略选位则顺抽。 |
| `show` | `--scope --run [--output-root PATH] [--zip-board]`。仅渲染已揭牌状态。返回 `board`、`images`、可用时 `overview`，另含有序的牌名、牌位、方向。`--zip-board` 同时返回使用 900 像素长边牌图的单文件 `board_zip`，用于限制附件类型和大小的宿主。正常 `board` 仍使用高清原图。文件采用原子替换，失败后可重试。 |
| `meaning` | `--scope --run` 读取该轮抽到的方向对应的释义，也支持 `--card ID --orientation upright\|reversed` 的明确查牌和过期结果人工重建。常规抽牌工作流在读解授权与交付后才调用。 |
| `clear` | `--scope --run` 取消或清除本轮。关闭的请求在本地库仅保留随机标识的摘要和关闭原因，用来拒绝迟到的 `start`。下一次成功加载素材的命令或 `clear` 清理本地已存在状态中超过 24 小时的轮次。`cleanup_pending: true` 表示本轮已不可访问，私有牌桌文件仍待下次重试清理。主动导出到宿主交付目录的文件由宿主管理。 |

状态由 `prepared` 转为 `revealed`，然后可继续 `show`、`meaning` 或清除。牌堆、方向、素材版本、时间和快照写入 SQLite。资产和牌阵升级导致版本变动时，旧轮次返回明确错误，保持原快照。SQLite 写操作串行化，两个揭牌调用只能提交一个快照。程序前置条件和 Agent 对话闸口分工明确，终端程序无从凭空验证操作者的真实意图。

## 文件与交付

- `tarot-it/SKILL.md` 是四端共用入口。`references/hosts.md` 说明官方安装目录、工具权限、发图语法、失败回退和可复现的验收步骤。
- `references/cards/*.json` 为逐牌资料，`references/spreads.json` 定义牌位。`assets/deck/manifest.json` 把固定来源及实际文件映射到卡 ID。生成预览需要构建端 Pillow，运行端可无 Pillow，复杂牌阵仍有带布局的 HTML。
- `show` 在单轮目录写尺寸适合发图的 JPEG。逆位预览在构建时已旋转 180°，高清原图由 HTML 按实际方向显示。可选 PNG 总览用于多牌，遵循目标端附件限制。离线 HTML 嵌入 JPEG，使用本地样式，图上有牌位与方向文字。
- 图形端目标为 OpenClaw Control UI、Hermes 支持图片的 Gateway、Codex macOS Desktop。纯终端目标为 Hermes CLI、Codex CLI、Claude Code CLI。按各宿主可用的原生附件、文件预览或离线牌桌交付。OpenClaw 和 Hermes 的首版交付以官方接口适配为准，实际消息渠道的结果以记录的接收证据为准。
- 根目录 `README.md` 说明安装、卸载、依赖和快速体验。发布构建只装入独立 Skill 的允许文件，生成带版本的 ZIP 和 SHA-256。构建前确认材料再分发依据，公开发布还须通过宿主效果与现代校读验收，并由权利人确认代码和原创内容的分发条款。

## 验证与记录

1. **宿主接口。** 对照 OpenClaw 和 Hermes 官方文档记录安装及发图路径。Codex 与 Claude Code 用真实牌图验收交付。已有临时环境实测保留版本和结果。
2. **工程。** 校验 78 个牌面、156 条释义、8 套牌位；测试所有牌阵、无逆位、重复请求、并发揭牌、隔离、轮次过期、错误输入、揭牌前隐藏、素材损坏、离线牌桌和窄屏布局。测试应检查输出的牌名、方向和图像，不能只检查进程退出状态。
3. **对话。** 使用不同请求验证直接抽、带仪式、只翻牌、事先同意解读、事后要求解读、越界改写和危机停止，同时检查重复补传保留原牌。
4. **包。** 校验 Skill 格式、ZIP 成员与哈希，从干净的带空格路径解压并运行。证据写入 `docs/验收记录.md`，逐项区分已通过、仅协议验证、因环境未运行和资料待校读。
