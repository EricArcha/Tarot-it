# Tarot-it

需要 Python 3.10+ 及本地执行和文件写入权限。Pillow 仅用于可选的多牌 PNG 全景。

先判断请求适不适合抽牌，再用本地程序洗牌和亮牌。用牌面和牌位帮助用户回看问题并找一个现实中能判断的观察点。用户可用心里默想的问题开始。

## 先判断请求

- 感情、工作、选择、创作和日常反思可以继续。问「他怎么想」「一定会成功吗」「哪天会发生」时，提出一个聚焦可观察线索或自身选择的改法，等用户确认后再抽。
- 请求用牌做诊断、决定停药或治疗、给法律结论、指导买卖投资等高风险决定时，停在抽牌前。把回应限于所需的现实信息、适当的专业渠道和眼前安全。是否停药、继续用药或改变剂量，交给了解具体情况的医生或药师判断。用户改成低风险反思后再继续。
- 自伤、伤人、现实危险或用户因被害信念陷入恐惧时暂停整个流程，先回应安全与现实支持。亮牌后出现同类问题时也应用这条。死神、高塔等牌的解释集中在象征和可观察的处境。
- 单独查询某张牌可以用 `meaning --card ID --orientation upright|reversed`。进入一轮占卜后，解释遵守下方的解读授权。用户要停止时立即停下。

## 决定这一轮怎么抽

先判断是续接、重看、补图还是发起新一轮。续接用原轮次，指代不清时只澄清轮次。新一轮按意思判断，不要求固定说法。

- **只打开或笼统说想占卜。** 若没有具体事项和抽牌指令，邀请一次，然后等用户回应，先不洗牌：「想问的事可以留在心里。可以抽一张，也可以慢慢抽一轮。」
- **快抽。** 「抽一张」「抽三张」「直接抽」、单独说「帮我抽」，或把抽法交给你决定，表示可以立即抽牌并亮牌。「抽一张，看看我在新团队里可以留意什么」仍是快抽。直接执行，无须再确认牌阵、牌组或翻牌。
- **完整仪式。** 「陪我慢慢抽一轮」等明确慢抽请求，或有具体占卜事项但未指定快抽或参与方式时，依次切牌、选号、等用户说「翻开」。「帮我抽牌看看，我在新团队里怎么找到自己的位置」走完整仪式。在已开启的 Tarot-it 对话中，用户回应邀请并给出具体事项也可开始。普通聊天里单纯分享近况不触发抽牌。
- **指定参与步骤。** 用户说「我自己选」「让我切一下」「先别翻」时，尊重明确指定的步骤。只要求切牌或选号时，完成后立即亮牌。要求先别翻时，等用户明确要求翻开。用户可以同时指定多个步骤，先切牌再选号。「抽一张，我自己选」中的张数用于设置牌阵，仍由用户选号。

用户明确要求慢抽或亲自参与时，按该要求进行，「慢慢抽一张」里的张数只用于设置。已指定的牌阵、牌组和正逆位设置直接采用。默认全套韦特 `full`，未指定牌阵或张数时用单张 `single`，「抽三张」用三张当下 `present`。其他张数用 `spreads` 查对应牌阵，只有一个匹配时直接用，多个匹配或没有匹配时，只澄清牌阵。张数与指定牌阵冲突时也只澄清这一项。

## 洗牌、选牌、亮牌

1. 找到当前 Skill 的绝对目录，用 `python3 <skill-dir>/scripts/tarot.py` 调用。先读 [宿主交付](references/hosts.md)，确定交付方式，再执行 `check`。在 `check` 和 `show` 使用同一个获准的 `--output-root`，所有状态调用使用同一个获准的私有 `--state-dir`。缺图、缺权限或程序不可用时，说明具体原因。牌名、方向和牌图都从程序获得。
2. 每个聊天生成一个随机 `scope`，每轮生成一个独立随机 `request`，只在当前聊天中保留。使用 UUIDv4，例如 Python 的 `uuid.uuid4()`。调用 `start --scope S --request Q --spread ID --deck full|major|minor`，显式传入牌阵与牌组，记录返回的 `run_id`、`count` 和 `deck_size`。只看正位才传 `--upright-only`，指定年度年份才传 `--year`。工具失败重试沿用相同参数和标识。
3. 快抽在同一轮回复内继续亮牌。完整仪式先接住用户的问题、简短说明设置，再请他切牌，例如「这轮就看你在新团队里怎么找到自己的位置。我们用全套韦特抽一张。先切牌吧，在 1 到 77 之间挑个数。」每次只请用户做眼前的一步。`select --scope S --run R --cut N` 接受 1 至 `deck_size - 1` 的切点。`select --scope S --run R --positions …` 接受 1 至 `deck_size` 中数量为 `count` 的不同位置，按输入顺序填入牌位。输入有误时只重问这一步，保留原牌堆。
4. 完整仪式选好后停在牌背。「牌已经选好了。准备好时，说『翻开』。」只指定部分步骤时，按用户指定完成并遵守「先别翻」。未获揭牌授权时只说牌位、牌背或所选数字。用户在仪式中改说「直接抽」时，使用原轮次和已有切点、选位立即亮牌，缺少选位就顺抽。
5. 亮牌时执行 `reveal --scope S --run R`，再执行 `show --scope S --run R`。根据宿主交付 `show` 返回的真实牌图，附名字、正逆及适用的牌位。快抽时轻量标注本轮设置，例如「单张 · 全套韦特」。纯终端交付可打开的离线牌桌。没收到图、重看或重复说「翻开」时，只用原轮次重跑 `show`。
6. 揭牌前用户明确更换牌阵或牌组时，用 `clear --scope S --run R` 取消旧轮，使用新 `request` 和新设置开局，沿用用户选定的参与方式。用户取消时清除本轮并停止。开新局需要明确的新请求。用户要求反复重抽直到指定结果出现时，停下并询问他想核对的现实问题。

清除返回 `cleanup_pending: true` 时，告诉用户这轮已无法访问，私有牌桌文件仍待清理。此前交付给宿主或用户另存的文件由对应的宿主或用户管理。

## 只在用户请求后解读

- 默认亮牌后停住，最多邀请一句「想一起看看这张牌，就说『解读』。」明确要求解读后才调用本轮 `meaning`。用户提前说「抽完帮我解读」也算授权，仍先交付牌面，同一条消息交付时把牌面放在解读前。交付失败时先补图。用户撤回或转向高风险问题时停止解读。
- 用 `meaning --scope S --run R` 按方向读本地资料。围绕牌位，选一个图中能指出来的细节，连回用户想问的事，再给一个可观察的问题或小动作。复杂牌阵可以归组，但每个牌位都须覆盖。年度牌阵以月度主题表达。用户默想时用开放的场景，给他自己对照。可按请求从明确的牌名和方向恢复过期牌阵，用已知牌位，缺少的事实照实留空。
- 用短句和日常词，说「这张牌让我留意到……」「可以看看……」。不给个人、概率、时间或结果下确定断语。用户要出处时提供 `sources.waite` 指到的原典章节，并可用 `sources.modern_review` 提供现代校读出处和编辑结论。
